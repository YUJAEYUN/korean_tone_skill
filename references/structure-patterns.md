# 정보 전달 글의 논리 구조 템플릿

수능 비문학 지문에서 뽑아 쓸 만한 건 문장이 아니라 **문단을 어느 순서로 배치하는가**뿐입니다.
그래서 이 파일도 딱 거기까지만 다룹니다. 어떤 단어를 쓸지, 문장을 얼마나 복잡하게 쓸지는
`plain-vocabulary-map.md`와 `genre-rules.md`의 몫입니다. 비문학 지문 특유의 문장
자체(한자어 밀도, 절 접속 방식, 문어체 어미)는 따라 하지 않습니다 — 그건 이 스킬이
없애려는 것과 방향이 같습니다.

이 템플릿은 SKILL.md 2단계에서 텍스트가 **정보 전달(설명글)** 로 판별되었을 때만
참조합니다. 에세이/실용문에는 적용하지 않습니다.

## 언제 쓰는가

원문이 이미 특정 순서로 쓰여 있어도, 독자가 따라가기 어렵게 배치되어 있다면(예: 예시가
개념 설명보다 훨씬 뒤에 나오거나, 한계점이 장점 설명 중간에 끼어드는 경우) 아래 패턴
중 가장 가까운 것을 기준으로 문단 순서를 재배치할 것을 검토합니다. 이미 자연스러운
순서라면 그대로 둡니다 — 구조 재배치는 "필요할 때만" 하는 선택지입니다.

## 패턴 목록

| 패턴 | 설명 | 수능 비문학에서 배울 점 |
|---|---|---|
| 정의 → 필요성 → 작동 원리 → 한계/전망 | 개념 설명형 정보글의 기본 골격 | 비문학 지문이 낯선 개념을 도입하는 순서 (먼저 "무엇인가"를 정의하고, 나서야 세부로 들어감) |
| 대조 구조 | A와 B를 견주며 설명 | 지문 내 "반면", "이와 달리" 앞뒤로 문단이 나뉘는 배치 방식 |
| 인과 사슬 | 원인 → 결과를 단계적으로 제시 | 논리 비약 없이 원인-결과 고리를 한 단계씩 쪼개는 방식 |
| 예시 배치 시점 | 추상 개념을 설명한 직후 곧바로 구체적 예시를 삽입 | 비문학이 예시를 뒤로 미루지 않고 개념 직후에 바로 붙이는 습관 |

### 1. 정의 → 필요성 → 작동 원리 → 한계/전망

새로운 개념·기술·제도를 소개하는 글에 기본적으로 적용합니다.

1. **정의**: 이게 무엇인지 한두 문장으로 먼저 밝힌다.
2. **필요성**: 왜 이게 등장했는지, 어떤 문제를 해결하는지.
3. **작동 원리**: 실제로 어떻게 작동/적용되는지, 구체적 예시 포함.
4. **한계/전망**: 한계나 앞으로의 과제.

이 순서를 뒤섞으면(예: 한계부터 이야기하고 나중에 정의) 독자가 맥락 없이 읽게 됩니다.

### 2. 대조 구조

두 대상(구제도 vs 신제도, A방식 vs B방식 등)을 비교하는 글에 씁니다. 한쪽을 통째로
설명한 뒤 다른 쪽을 통째로 설명하기보다, **같은 기준(비용/속도/안전성 등)을 하나씩
잡아 A와 B를 번갈아 대조**하면 독자가 비교점을 놓치지 않습니다.

### 3. 인과 사슬

"A 때문에 B가 일어났고, B 때문에 C가 일어났다"처럼 여러 단계를 거치는 설명에 씁니다.
중간 단계를 생략하고 "A 때문에 C다"로 건너뛰면 논리 비약으로 읽히므로, 각 단계를
한 문단씩 분리합니다. (단, 4단계 의미 보존 검증에서 원문의 인과관계 방향을 절대
바꾸지 않도록 주의합니다.)

### 4. 예시 배치 시점

추상적인 개념을 설명한 문단 바로 다음에 구체적인 예시를 붙입니다. "예시는 글 끝에
몰아서"가 아니라 "개념 하나당 예시 하나를 즉시" 배치하는 것이 쉬운 글의 핵심입니다.
