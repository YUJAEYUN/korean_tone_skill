# korean-plain-writer

AI 티 나는 한국어(번역투·명사화·상투어·어려운 한자어)를 없애고, 어떤 주제든 **쉬운 표준
한국어**로 읽히도록 재작성하는 스킬입니다.

이 스킬은 두 개의 서로 다른 질문에 답합니다.

1. **"무엇이 어색한가?"**: AI체 진단입니다. 새로 만들지 않고 검증된 외부 카탈로그를
   그대로 씁니다. 요약은 `references/ai-tell-catalog.md`에, 실제 판정 기준 전문은
   `vendor/humanizer/`에 있습니다(원본: DaleSeo/korean-skills의 humanizer).
2. **"그럼 대신 어떻게 써야 하는가?"**: 목표 문체 적용입니다. 이 스킬의 핵심 부가가치이며,
   `references/plain-vocabulary-map.md`, `references/structure-patterns.md`,
   `references/genre-rules.md`, `examples/pairs/`로 구성됩니다.

**의미 보존이 최우선**입니다. 윤문 과정에서 사실관계·수치·주장 방향이 바뀌면 안 되며, 이는
아래 4단계에서 강제로 검증합니다.

## 언제 이 스킬을 쓰는가

- 사용자가 "이 글 쉽게 고쳐줘", "AI가 쓴 것 같은 느낌 없애줘", "쉬운 말로 풀어줘",
  "표준 한국어로 바꿔줘" 등을 요청할 때
- 번역투/한자어가 많은 보고서, 에세이, 안내문을 다듬어 달라고 할 때
- "진단만 해줘" (재작성 없이 문제점만 보고)를 요청할 때 → 아래 3단계는 생략하고 1단계 결과만 보고

## 파이프라인

### 1단계: AI체 진단 (참조: `references/ai-tell-catalog.md`)

입력 텍스트를 6개 카테고리(문장부호/띄어쓰기/품사 다양성/어휘/문장 구조/번역투) 기준으로
훑어 패턴을 찾고, 각 발견을 심각도로 태깅합니다.

- **S1 (결정적)**: 한 번만 나와도 AI 신호. 무조건 수정 권장.
- **S2 (강함)**: 1~2회는 허용, 3회 이상 반복되면 AI 신호.
- **S3 (약함)**: 단독으로는 약하지만 다른 패턴과 겹치면 결정적.

패턴의 상세 정의와 예시는 필요할 때만 `references/ai-tell-catalog.md`를 열어 참조하세요.
모든 패턴을 매번 전부 로드할 필요는 없습니다(progressive disclosure).

이 6개 카테고리와는 별도로, **조어형 추상 개념어**(없는 개념에 그럴듯한 이름을 붙이는
패턴)도 확인합니다. 자세한 판별법은 `references/fabricated-terms.md` 참조.

### 2단계: 장르·목적 판별

텍스트가 다음 중 무엇에 가까운지 먼저 판단합니다. 이 판단에 따라 3단계에서 참조할 파일이
달라집니다.

| 장르 | 특징 | 3단계에서 쓸 참조 |
|---|---|---|
| 정보 전달(설명글) | 개념·현상·절차를 설명 | `structure-patterns.md` + `plain-vocabulary-map.md` + `genre-rules.md`(정보 전달 행) |
| 의견/에세이 | 개인적 견해·경험·논증 | `plain-vocabulary-map.md` + `genre-rules.md`(의견/에세이 행, 구조 템플릿은 강제하지 않음) |
| 실용문(안내/공지/이메일) | 지시·안내·요청 | `plain-vocabulary-map.md` + `genre-rules.md`(실용문 행) |

애매하면 사용자에게 묻기보다, 텍스트에 가장 지배적인 목적을 기준으로 판단하고 어떤 장르로
처리했는지 결과에 명시하세요.

### 3단계: 목표 문체로 재작성 (이 스킬의 핵심)

1. `references/plain-vocabulary-map.md`를 참조해 어려운 한자어·추상어를 문맥에 맞게 치환합니다.
   표에 없는 단어도 같은 기준(일상어로 바꿔도 의미·격이 손실되지 않는가)으로 판단해서
   바꾸고, 새로 바꾼 표현은 답변 끝에 "이번에 새로 다듬은 표현"으로 짧게 적어 매핑표에
   반영하세요.
2. 정보 전달형 글이라면 `references/structure-patterns.md`의 문단 배치 패턴에 비추어 정보
   순서가 자연스러운지 점검하고 필요하면 재배치합니다. **문장 자체의 어휘 밀도나 접속 방식을
   수능 비문학처럼 만들지 않습니다.** 이 모듈은 순서에만 관여합니다.
3. `references/genre-rules.md`로 문장 길이 리듬과 톤을 장르에 맞추고, 장르 공통 원칙
   (고압적·차별적 표현, 접속어·조사 정확성, 부정문 대신 긍정문, 목록화)도 확인합니다.
4. `references/fabricated-terms.md`의 판별법으로 조어형 추상 개념어를 확인하고,
   조어로 판단되면 용어를 그대로 두지 말고 평범한 서술로 풀어씁니다.
5. `examples/pairs/`의 Before/After 사례를 필요시 참조해 감을 잡습니다(규칙 나열보다 실례가
   더 정확한 기준이 될 때가 많습니다).

### 4단계: 의미 보존 자체검증 (필수, 생략 불가)

재작성본을 출력하기 전에 아래 6항을 모두 확인합니다.

1. 원본의 숫자·날짜·인명·기관명·제품명이 모두 보존되었는가?
2. "X 때문에 Y"가 "Y 때문에 X"로 뒤바뀌지 않았는가? (인과관계 방향)
3. 있다/없다, 가능/불가능, 찬성/반대 등 부정·긍정이 반전되지 않았는가?
4. 큰따옴표 안 직접 인용은 원문 그대로인가?
5. 원본의 핵심 주장·결론이 바뀌지 않았는가?
6. 원본의 격식체/반말 수준이 일관되게 유지되었는가?

6항을 모두 통과하면 결과에 "✓ 의미 보존 검증: 6항 모두 통과"를 표시합니다. 하나라도 걸리면
출력 전에 재작성본을 수정하세요.

### 5단계: 변경률 확인

`scripts/change_rate_check.py`로 원문 대비 변경 비율을 계산합니다(순수 문장부호/띄어쓰기
변경은 제외). 이 숫자는 **참고 정보**이지, 막는 기준이 아닙니다. korean-plain-writer는
격식체를 쉬운 말로 통째로 재구성하는 경우가 많아서 변경률 자체가 큰 게 정상입니다.
예문 뱅크 45개를 이 스크립트로 실측한 결과 중앙값 88%, 범위 19~136%입니다
(`eval/README.md` 참고). DaleSeo/humanizer가 쓰는 30%/50% 임계값은 가벼운 손질을
전제로 한 기준이라 korean-plain-writer에는 맞지 않아 가져오지 않았습니다.

- **150% 미만**: 참고 수치로만 출력에 포함
- **150% 이상**: 예문 뱅크 관측 범위를 크게 벗어난 것이므로, 4단계 의미 보존
  체크리스트를 다시 확인하세요. 6항을 모두 통과했다면 그대로 출력해도 됩니다. 실제
  안전장치는 변경률이 아니라 그 체크리스트입니다.

## 출력 형식

1. 자연도 등급 (A~D, 아래 기준)
2. 감지된 패턴 요약 (S1/S2/S3 건수, 어느 카테고리인지)
3. 재작성본
4. 주요 변경 사항과 이유 (2단계에서 판별한 장르, 적용한 구조/어휘 조정 포함)
5. 변경률(참고 수치)
6. ✓ 의미 보존 검증 통과 여부

**자연도 등급**
- **A**: S1 0건 + S2 2건 이하
- **B**: S1 1~2건 또는 S2 3~5건
- **C**: S1 3건 이상 또는 S2 6건 이상
- **D**: 다중 카테고리 위반(S1 5건 이상 + S2 8건 이상) 또는 의미 보존 체크리스트를
  실패한 경우

## 진단 전용 모드

사용자가 "재작성 없이 진단만" 요청하면 1~2단계만 수행하고, 3~5단계는 생략한 채 발견된 패턴과
장르 판별 결과만 보고합니다.

## 참조 파일 안내

| 파일 | 언제 여는가 |
|---|---|

| `vendor/humanizer/references/*.md` | 1단계에서 감지된 카테고리의 정확한 판정 기준·예문이 필요할 때 |
| `references/fabricated-terms.md` | 1단계·3단계에서 조어형 추상 개념어가 의심될 때 |
| `references/structure-patterns.md` | 2단계에서 "정보 전달형"으로 판별했을 때만 |
| `references/plain-vocabulary-map.md` | 3단계 어휘 치환 시 항상 |
| `references/genre-rules.md` | 3단계 톤 조정 시 항상 |
| `examples/pairs/` | 감이 안 잡힐 때, 또는 사용자가 예시를 요청할 때 |
| `scripts/change_rate_check.py` | 5단계 변경률 계산 시 |
