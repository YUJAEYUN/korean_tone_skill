# 블라인드 A/B 결과 기록

`eval/README.md`의 방식대로, 라벨을 가린 채 사람에게 원문과 재작성본 중 어느 쪽이
더 자연스러운지 고르게 한 기록입니다. 날짜순으로 아래에 계속 추가합니다.

## 2026-09-14: 개선 라운드 1 (시제·상 체크리스트 항목, champion vs challenger)

전체 기록은 `eval/runs/2026-09-14-round1-tense-aspect/`에 있습니다.

- 가설: 4단계 의미 보존 체크리스트가 시제·상(진행/완료)을 명시적으로 점검하지
  않아, "쉬운 말로" 다듬다가 "~하고 있다"류 진행형을 지우면서 "아직 하는 중"이
  "이미 끝난 일"처럼 읽힐 수 있다.
- 변경: SKILL.md 4단계 체크리스트에 9번째 항목(시제·상 보존)만 추가. 다른 규칙,
  어휘 매핑표, 장르 규칙은 건드리지 않음(`challenger.diff` 참고).
- 결과: 이 라운드를 시작하기 전에 지난 파일럿에서 이미 본 `validation.jsonl` 6개
  사례를 `dev.jsonl`로 옮기고 새 6개(`val2-*`)로 교체했습니다(개선 프로토콜의
  validation 회전 규칙). 가설을 직접 겨냥한 2개 사례(`val2-tense-01`,
  `val2-casual-01`)에서 challenger 2승 0패, 0건 중대 실패. 무관한 4개 사례는
  champion과 challenger가 완전히 동일한 출력을 내 회귀 없음의 첫 신호를 보였습니다.
  판정은 `insufficient_evidence`(정책 기준 표본 미달) — 표본이 작을 때 나와야
  하는 정상적인 결과입니다.
- **라이브 스킬(`skills/korean-plain-writer/SKILL.md`)은 아직 고치지 않았습니다.**
  challenger는 별도 스냅샷(`challenger-skill/`)으로만 존재하며, 사람이 diff와
  경계 사례를 확인하고 승격을 결정하기 전까지 반영하지 않습니다.
- 이번에도 가설 수립·challenger 편집·채점을 모두 같은 세션이 해서 자기채점입니다.
  독립 채점자로 반복하기 전까지는 참고 신호입니다.
- **승격**: 사람이 diff와 사례를 직접 검토한 뒤 승격을 승인했습니다.
  `skills/korean-plain-writer/SKILL.md` v0.2.0 → v0.2.1. `report.json`의
  자동 판정은 여전히 `insufficient_evidence`이며, 정책 임계값을 낮추지 않고
  사람이 표본 부족을 알고도 수동으로 승인한 것입니다
  (`eval/runs/2026-09-14-round1-tense-aspect/promotion-manifest.json` 참고).

## 2026-09-14: 하네스 첫 정식 실행 (champion vs naive, 파일럿, 자기채점)

전체 기록은 `eval/runs/2026-09-14-champion-vs-naive/README.md`와 `report.md`에
있습니다. 여기서는 요지만 남깁니다.

- `eval_harness.py`의 `validate → scaffold → static-grade → make-blind → report`
  전 과정을 처음으로 실제 실행했습니다(`validation.jsonl` 6개 사례, trial 1회).
- challenger(개선 후보)가 아직 없어 `champion`(v0.2.0)과 `naive`(스킬 없이 일반
  윤문 프롬프트만) 두 계열만 비교했습니다. 자동으로 `comparison_only`로
  기록되며 승격 판정 대상이 아닙니다.
- **중요한 한계**: 출력 생성과 블라인드 채점(자연스러움·의미 보존)을 모두 같은
  세션·같은 모델이 했습니다. 라벨을 실제로 가리는 형식(`ballots.jsonl`만 보고
  판정)은 지켰지만, 독립적인 사람이나 다른 계열 모델 채점이 아닙니다. 아래
  숫자는 "하네스가 실제로 동작하고 최소 신호가 있다"는 파일럿 증거로만
  읽어야 합니다. `README.md`의 "다른 계열 LLM 채점자와 사람 2명 이상으로
  하네스 첫 정식 실행" TODO는 여전히 열려 있습니다.
- 결과: 유효 비교 5건(무승부 1건) 중 champion 5승. 결정적 검사에서 champion은
  6개 사례 모두 통과(과잉 수정 경보 0건), naive는 2건 중대 실패
  (`val-policy-01` must_preserve 문자열 불일치, `val-quote-01` 직접 인용을
  간접 화법으로 변형). 의미 게이트에서 champion 6/6 통과, naive 3/6 실패
  (원문에 없는 뉘앙스·감정 추가, 인용 변형). 이미 자연스러운 원문 3건에서
  champion은 전부 그대로 두었고 naive는 전부 불필요하게 손을 댔습니다.
- 표본이 정책 기준(유효 비교 20건 이상, 장르별 2건 이상)에 크게 못 미쳐
  `insufficient_evidence` 사유가 그대로 보고서에 남아 있습니다. 표본을 늘리고
  독립 채점자로 반복하기 전까지는 참고 신호 이상으로 쓰지 않습니다.

### 한계

- 평가자 1명, 항목 3개짜리 결과라 표본이 매우 작습니다. "이 스킬이 대체로 더

  첫 신호 정도로만 읽어야 합니다.
- 아직 "스킬 미적용 재작성"(그냥 "쉽게 써줘"라고만 시킨 결과) 비교군이 없어서, 이
  결과가 스킬의 구체적인 규칙(카탈로그, 구조 템플릿, 장르 규칙) 덕분인지 아니면
  단순히 "짧고 쉽게 쓰라"는 지시만으로도 나오는 차이인지 구분이 안 됩니다.
- 세 항목 다 원문이 명백히 번역투·명사화가 심한 텍스트였어서(의도적으로 그렇게
  작성함), 이미 잘 쓰인 원문에도 스킬이 도움이 되는지는 이번 라운드로는 알 수
  없습니다.
- 개선된 의미 게이트로 재검토하자 2개가 실패했다. 자연스러움과 의미 보존을 분리한
  현재 평가 하네스가 필요한 이유를 보여주는 과거 기록으로 유지합니다.
