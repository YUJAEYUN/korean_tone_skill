# Round 4: 긴 문장 나누기 — 효과 없음, 승격 안 함

## 가설과 변경

round3 champion 출력에서 18~23어절짜리 다절 문장(예: "~강화하는데, ~이루어지지 않으면
~흐트러지고 ~떨어집니다")이 어휘만 바뀐 채 남았다(fl-008). "한 문장에 하나의 정보" 규칙이
`genre-rules.md`에만 있고 SKILL.md 3단계는 "문장 길이 리듬"이라고만 요약하기 때문이라고
보고, SKILL.md 3단계 3번에 나누기 조건(절 셋 이상, 서로 다른 정보가 겹친 문장), 연결어미
관계 보존, 에세이 제외를 한 문단 덧붙였다(`challenger.diff`). 근거는 `experiment.yaml`.

## 방법

round3와 같다. round3 validation 10건은 dev로 옮기고 새로 무유도 생성한 10건(haiku 8편:
정보 3·공지 2·이메일 1·에세이 2, opus 2편: 자연스러운 메시지·후기)을 validation으로 썼다.
naive·champion·challenger 각 2회, 모두 sonnet Agent. 결정적 검사(`static-scores.jsonl`)는
80개 출력 중 중대 실패 0건, 과잉 수정 경보 0건.

## 결과

| heating | 5 / 16.0 | 5 / 15.2 | 5 / 14.6 | 5 / 15.4 | 5 / 15.4 |
| secondhand | 5 / 13.4 | 5 / 13.0 | 5 / 13.2 | 5 / 13.0 | 5 / 13.2 |
| elevator | 6 / 10.0 | 6 / 10.7 | 6 / 10.7 | 6 / 10.3 | 6 / 9.7 |
| friend (에세이) | 6 / 11.3 | 6 / 11.2 | 6 / 11.0 | **8 / 8.2** | 6 / 11.3 |
| 나머지 5건 | 문장 수 변화 없음 | | | | |

challenger가 문장 경계를 바꾼 것은 20회 중 2회였고, 그중 하나는 규칙이 제외한 에세이였다.
champion·challenger 출력 간 유사도는 0.934로, 같은 스킬을 두 번 돌린 출력끼리의 0.929와
같은 수준이다.

에세이를 나눈 1건은 퇴행이 아니었다. 원문 "대학교 입학과 동시에 다른 도시로 떠난 내가,
그리고 제 자리에서 계속 살아가는 친구가 공유할 수 있는 일상이 점점 줄어들었다"는 주어가
꼬인 문장이고, challenger는 이를 "나는 대학에 입학하면서 다른 도시로 떠났고, 친구는 그
자리에 그대로 남았다. 그러면서 …"로 풀었다. 규칙 문구와는 어긋나지만 고칠 만한 문장이었다.

## 왜 안 됐나

- **새 원문에 가설 대상이 거의 없었다.** 이번 원문에서 가장 긴 문장은 17~18어절, 절 2개였다
  (heating "창문틈에 … 최소화하고, 밤에는 … 높일 수 있습니다", caffeine "… 다르지만, 일반적으로
  … 좋습니다"). 후보 규칙의 발동 조건(절 셋 이상 또는 서로 다른 정보가 겹침)에 걸리지 않는다.
  round3 원문의 22~23어절·4절 문장과 달리, 무유도 생성 원문은 매번 다른 분포로 나와서
  dev에서 본 실패가 validation에 재현된다는 보장이 없다.
- 실행 Agent들의 보고를 보면, 모두 "원문이 이미 비교적 쉬워 어휘·번역투만 정리"했다고 판단했다.
  3단계 7번("이미 자연스러우면 패턴 제거 자체를 목표로 삼지 않는다")이 우선했다.

## 블라인드 채점을 하지 않은 이유

round3와 같다. 두 스킬 출력 차이가 반복 실행 편차 안에 있어 쌍대 채점은 실행 잡음을
채점하게 된다. 절차에서 벗어난 판단이므로 기록해 둔다.

## 결정과 교훈

- 승격하지 않는다. diff와 기록만 남긴다.
- round3·round4가 같은 모양으로 끝났다. SKILL.md에 문단을 더해도 실행 Agent의 행동이 편차
  이상으로 바뀌지 않았고, 두 번 다 새 validation 원문에 가설 대상 실패가 약하게만 들어 있었다.
- 다음 라운드부터는 패치를 쓰기 전에 **validation 원문에 대상 실패가 실제로 있는지 먼저
  확인한다.** 예: 문장 나누기라면 `text_metrics.py`로 원문 최대 문장 길이·절 수를 보고 기준에
  걸리는 문장이 사례마다 있는지 확인한 뒤 사례를 확정한다. 무유도 생성은 유지하되, 생성 후
  "대상 실패를 포함한 글"만 고르는 선별 단계를 둔다. 선별 기준은 사례를 보기 전에 정한다.
- 이번 validation 10건은 결과를 봤으므로 다음 라운드 전에 dev로 옮긴다.
