# 변경률 기준선 실측 (예문 뱅크 45개)

`scripts/change_rate_check.py`의 임계값을 정하려고 `examples/pairs/`의 45개 Before/After
쌍 전부를 이 스크립트로 직접 측정한 기록입니다. 재현하려면 각 파일의 Before/After
블록을 파싱해 `check_change_rate(before, after)`를 호출하면 됩니다.

## 결과

| 파일 | 정상(150% 미만) | 이례적(150% 이상) |
|---|--:|--:|
| informational.md (15개) | 15 | 0 |
| essay.md (15개) | 15 | 0 |
| practical.md (15개) | 15 | 0 |
| **합계** | **45** | **0** |

- 최솟값: 19%("격식체 불일치: 취미". 원문과 재작성본이 이미 거의 같아서 변경이 적음)
- 최댓값: 136%("피동 남용: 백신". 이중 피동 표현을 능동형으로 완전히 갈아엎음)
- 중앙값: 88%
- 평균: 84%
- 1사분위수: 74%, 3사분위수: 100%

## 원래 임계값(30%/50%)으로 측정했다면

DaleSeo/humanizer의 원래 임계값을 그대로 적용했다면 45개 중 41개(91%)가 "50% 초과"
(원본 기준 "stop", 출력을 멈추고 사용자에게 확인을 구하는 단계)에 해당했습니다.
이 45개는 전부 이 스킬이 목표로 하는 좋은 재작성 예시이므로, 원래 임계값이
korean-plain-writer에는 맞지 않는다는 걸 보여줍니다.

## 결론

이 실측을 근거로 `scripts/change_rate_check.py`의 상한을 150%로 올리고, 가드의
성격을 "출력을 막는 것"에서 "참고 수치를 보여주는 것"으로 바꿨습니다. 자세한 내용은
`references/ai-tell-catalog.md`의 "변경률 확인" 절 참고.
