# 평가 방법

`examples/pairs/`는 스킬이 학습·참조하는 자료입니다. 그 예시로 스킬을 재검사하면
순환논리가 됩니다("우리가 고치는 기준으로 우리가 고쳤는지"만 확인하게 됨). 그래서
평가는 `examples/pairs/`와 겹치지 않는 새 텍스트로, 다음 네 가지를 따로 봅니다.
텍스트 스타일 전이(Text Style Transfer) 분야가 표준으로 쓰는 스타일·내용·유창성
3축 평가를 참고했습니다(근거는 `related-work.md` 참고).

## 1. 자기 카탈로그 재검사 (보조 지표, 이것만으로는 부족)

`vendor/humanizer/`의 40패턴 기준으로 재작성본에 S1/S2/S3가 얼마나 남았는지 확인합니다.
"AI체 패턴이 없어졌는가"는 확인되지만 "사람 글처럼 잘 읽히는가"는 확인되지 않으므로
단독으로 성능 판단에 쓰지 않습니다.

## 2. 블라인드 A/B: 자연스러움 (핵심 지표)

held-out 텍스트(`holdout/`, 예문뱅크와 겹치지 않는 새 주제)를 스킬로 재작성한 뒤,
원문과 재작성본을 **어느 쪽이 원문인지 알리지 않고** 사람에게 제시해 "어느 쪽이 더
자연스러운가"를 판단하게 합니다. 순서는 매번 무작위로 섞습니다. 라벨을 미리 알면
판단이 왜곡되므로(원문이라고 하면 더 어색하게 느껴지는 식) 반드시 가린 채로 물어야
합니다.

- 평가자 1명의 판단은 노이즈가 클 수 있으니, 가능하면 2명 이상에게 물어보고 평가자
  간 판단이 얼마나 일치하는지 봅니다(근거: `related-work.md` 2번). 평가자를 늘리기
  어려우면 Claude를 보조 채점자로 써서 항목 수를 늘리되, 사람 판단을 대체하지는
  않습니다(`related-work.md` 3번).
- 나중에 "스킬 미적용 재작성"(그냥 "쉽게 써줘"라고만 시킨 결과) 같은 비교군을 추가하면
  스킬 자체의 기여분을 더 정확히 볼 수 있습니다. 지금은 원문 vs 재작성본 비교부터
  시작합니다.

## 3. 유창성 체크 (자연도와 별개 축)

`fluency-rubric.md`로 채점합니다. "AI체 패턴이 없어졌다"와 "문법적으로 매끄럽다"는
서로 다른 축입니다. 패턴을 없애려다 오히려 어색한 문장이 될 수 있으므로 따로 확인하고,
자연도 등급과 맞바꾸지 않습니다.

## 4. 의미 보존 게이트 (별도 채점, 트레이드오프 금지)

`meaning-preservation-rubric.md`로 채점합니다. 자연스러움 점수가 아무리 좋아도 이
게이트를 하나라도 실패하면 그 결과는 실패로 처리합니다. 자연스러움과 의미 보존을
하나의 점수로 섞지 않습니다.

의학 논문을 쉬운 요약으로 바꾸는 실제 연구에서도 "쉽게 쓰려는 의도"와 "실제로
쉬워졌는가"는 별개였습니다(`related-work.md` 6번). 규칙을 적용했다고 결과가
저절로 좋아진다고 가정하지 말고, 매번 이 게이트로 직접 확인합니다.

## 폴더

- `holdout/`: 평가용 원문(장르당 최소 1개, `examples/pairs/`와 주제 겹치지 않게)과
  그 재작성본. 각 파일에 진단 결과, 재작성본, 변경률, 의미 보존 체크 결과를 함께 기록.
- `meaning-preservation-rubric.md`: 4번 게이트에 쓰는 채점표.
- `fluency-rubric.md`: 3번 체크에 쓰는 채점표.
- `related-work.md`: 이 평가 방법과 좋은 글쓰기 기준의 근거가 된 논문·공식 자료.
- `change-rate-baseline.md`: 변경률 임계값을 재조정한 실측 근거.

## 결과 기록

블라인드 판단 결과(어느 회차에 누가 무엇을 골랐는지)는 `results.md`에 날짜순으로
남깁니다.
