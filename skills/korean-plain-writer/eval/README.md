# 평가 체계

이 폴더는 규칙을 잘 지켰는지 보지 않는다. 결과가 실제로 더 좋아졌는지를 본다.
제품의 목표와 절대 실패 조건은 `product-contract.md`, 실행 명령과 데이터 형식은
`HARNESS.md`를 따른다.

## 평가 원칙

1. **의미가 틀리면 다른 게 아무리 좋아도 통과시키지 않는다.** 자연스러움 점수로 의미
   왜곡을 상쇄하지 않는 절대 기준(게이트)이다.
2. 원문, 단순 프롬프트, 현재 스킬, 후보 스킬을 같은 기반 모델·설정에서 비교해서 뭐가
   좋아진 원인인지 구분한다.
3. 자연스러움 판단은 시스템 이름과 좌우 순서를 가린 쌍대평가로 한다.
4. **모델과 스킬을 동시에 바꾸지 않는다** — 한 번에 한 쪽만 바꿔야 뭐가 원인인지 알 수
   있다.
5. 생성 결과는 매번 조금씩 다르게 나올 수 있어서, 사례마다 여러 trial을 실행해 우연을
   걸러낸다.
6. 개선 AI는 비공개 테스트·정답 키·승격 정책을 수정할 수 없다. 개선자와 채점자가 같으면
   자기 채점이 되기 때문이다.
7. 자동 기준은 "사람이 검토할 만한가"까지만 판정하고, 실제 승격 여부는 사람이 정한다.
   다만 이 세션에서는 표본이 정책 기준에 못 미쳐도 사람이 diff와 근거를 직접 검토하고
   승격을 승인한 적이 여러 번 있다(라운드 1, 2b). 자동 기준 자체를 낮추지는 않았다 —
   그 위에 사람의 판단을 하나 더 얹은 것이다.

## 측정 축

| 축 | 성격 | 측정 방법 |
|---|---|---|
| 의미·사실 보존 | 절대 게이트 | 코드 검사 + `judges/semantic-gate.md` |
| 자연스러움 | 핵심 선호 지표 | 블라인드 쌍대평가 |
| 목소리·격식 | 독립 품질 축 | 쌍대평가 이유 태그 + 사람 표본 검토 |
| 유창성 | 독립 품질 축 | `fluency-rubric.md` |
| AI체 패턴 잔존 | 진단 지표 | vendor 카탈로그 S1/S2/S3 |
| 과잉 수정 | 회귀 지표 | 자연 원문의 변경량 경보 + 사람 판단 |
| 비용·지연 | 운영 지표 | 실행 manifest와 provider 로그 |

S1/S2/S3 개수는 사람 자연스러움의 대리값일 뿐이므로 “자연도 등급”이라고 부르지 않는다.
변경률은 품질 점수로 쓰지 않는다. 이상치를 찾는 보조 정보로만 쓴다.

## 데이터

- `cases/dev.jsonl`: 12개. 개선 과정에서 자유롭게 사용한다.
- `cases/validation.jsonl`: 6개. 후보 비교에 사용한다.
- `cases/private-template.jsonl`: 형식만 보여주는 예시 파일. 저장소 밖 비공개 테스트는
  따로 둔다.
- `holdout/`: 2026-09-08의 공개된 첫 실험 기록이다. 결과를 이미 봤으므로 더 이상
  홀드아웃으로 취급하지 않는다.

초기 데이터는 하네스 동작과 위험 범주를 검증하기 위한 seed다. 실제 사용에서 발생한 실패를
익명화해 장르·길이·격식·원문 품질별로 보강한다. 같은 사례를 고친 뒤 그 사례의 점수 상승을
일반화 증거로 사용하지 않는다.

## 채점자 운영

코드 검사는 숫자·인용·명시적 필수 문자열과, `vendor/humanizer`에서 검증된 문법·AI체
패턴 중 정규식으로 안전하게 잡히는 것(이중 피동, "에 있어서" 등)을 맡는다
(`HARNESS.md`의 "결정론적 문법·AI체 패턴 검사" 참고). LLM 채점자는 의미와
주관적 품질을 확장해서 보되, 생성 모델과 가능하면 다른 모델 계열을 사용하고 좌우를 바꾼
거울쌍을 평가한다. 사람은 무작위 표본, 채점자 불일치, 중대 실패를 검토해 자동 채점기와의
일치도를 주기적으로 확인한다.

최소 비교 수와 후보 승률 기준은 `policy.json`에서 버전 관리한다. 후보의 점수를 본 다음
정책을 바꿨다면 그 후보에는 새 정책을 소급 적용하지 않는다.

## 기존 첫 실험의 재해석

2026-09-08 실험에서 사람은 재작성본을 3/3 선택했다. 그러나 2026-09-13에 누락·추가를 포함한
새 의미 게이트로 재검토하자 1/3만 통과했다. 자연스럽게 보이는 글도 원문에 없는 사례를 넣거나
의미 범위를 좁힐 수 있다는 실제 회귀 사례다. 세부 기록은 `results.md`와 `holdout/`에 남긴다.

## 관련 파일

- `product-contract.md`: 도구의 철학을 검증 가능한 행동으로 정의
- `HARNESS.md`: 실행 절차와 JSONL 계약
- `improvement-protocol.md`: 개선 AI의 입력·권한·중단 조건
- `policy.json`: 승격 기준
- `baselines/naive.md`: 스킬 기여분을 재는 고정 단순 프롬프트
- `judges/`: 의미 게이트와 블라인드 채점 지침
- `schemas/`: 구조화된 모델 출력을 가져오기 위한 JSON Schema
- `related-work.md`: 평가 설계의 연구·공식 자료 근거
- `results.md`: 사람 평가의 역사적 기록
- `change-rate-baseline.md`: 변경률이 품질 게이트가 될 수 없는 이유
